# Правила для агентов

Проект пока на этапе исследования. Не начинайте реализацию браузера, пока в `docs/roadmap.md` не отмечены прототипы и ADR с выбором архитектуры.

Перед задачей прочитайте только относящиеся к ней разделы `docs/product-spec.md`, `docs/prototype-plan.md` и `docs/agent-workflow.md`. Отдельно отмечайте подтверждённые факты, предположения и результаты проверок.

## Работа вместе

- Координатор разбивает работу на независимые задачи с ожидаемым результатом и путём проверки.
- Пишущий агент владеет своими файлами на время задачи. Другой агент делает ревью, не редактируя эти файлы одновременно.
- Каждое изменение идёт отдельной веткой и через PR. В описании: что изменилось, почему, как проверено, какие ОС затронуты, что остаётся неизвестным.
- Ревьюер проверяет поведение, безопасность, кроссплатформенность и тесты. Автор исправляет замечания. Координатор объединяет только прошедшие проверки изменения.
- Роли из `.codex/agents/` используются по задаче. Не запускайте несколько пишущих агентов на одни файлы или одну ветку.
- Не утверждать, что ошибка исключена. Фиксировать известные ограничения и добавлять регрессионную проверку для найденного дефекта.

## Обязательные инварианты для ревью

- Не смешивать данные профилей и приватного окна. Для нового хранилища показать тест изоляции и удаления временных данных.
- Веб-контент считать недоверенным. Не давать странице доступ к файловой системе и внутренним командам без явного разрешения и проверки границы.
- Не объявлять прирост скорости без воспроизводимого сравнения на том же устройстве и ОС.
- На Windows не отключать SmartScreen ради работы WebView2. Любое изменение защитных аргументов требует отдельной проверки безопасности.

Форматирование и обычные линтеры проверяются CI. Правила ревью здесь относятся к решениям, которые CI не может оценить по одному синтаксису.
