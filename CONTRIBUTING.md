# Как участвовать в Search

Search пока исследует архитектуру браузера. Основной код начинается после сравнения прототипов и ADR в `docs/roadmap.md`.

1. Перед работой прочитайте `AGENTS.md` и относящиеся к задаче разделы `docs/product-spec.md` и `docs/prototype-plan.md`.
2. Для заметного изменения сначала откройте issue: цель, затронутые ОС, критерии проверки и риски. Не начинайте параллельные правки одних файлов.
3. Работайте в отдельной ветке. В PR опишите что изменилось, почему, как проверено на каждой затронутой ОС и что осталось неизвестным.
4. Дождитесь CI и независимого ревью. Замечания с воспроизведением исправьте и повторно проверьте. Отсутствие замечаний не означает отсутствие ошибок.
5. Для дефекта добавьте регрессионный сценарий. Для изменений хранения данных, разрешений или связи страницы с приложением покажите отрицательные проверки.

Не публикуйте в issue, PR и логах токены, cookies, личные данные и подробности уязвимостей. Для уязвимостей следуйте [правилам безопасности](SECURITY.md).
