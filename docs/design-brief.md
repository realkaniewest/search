# Дизайн-бриф

Интерфейс разрабатывается отдельным этапом. Пока не утверждаем цвета, логотип, шрифты и макеты.

Цель: спокойный, узнаваемый браузер, в котором страница остаётся главным элементом. Нужны быстрые действия с клавиатуры, ясное состояние вкладок и понятные сигналы о загрузке, разрешениях и приватном режиме.

Решение по компоновке: вкладки Search постоянно расположены сверху. Боковую панель вкладок и переключатель на неё не проектируем. Для первой версии верхней панели ориентиром служит привычная пользователю компактность Safari: видимые вкладки, адресное поле и основные действия в одной спокойной композиции. Дизайн, размеры, иконки и поведение Search разрабатываем самостоятельно, без копирования интерфейса Safari.

У Arc изучить организацию рабочих контекстов и быстрый вызов действий, не перенося боковые вкладки, макеты, иконки, названия элементов и визуальные детали. Отдельный режим разработки может показывать дополнительные инструменты по запросу; обычный экран остаётся простым. Режим и набор инструментов пока гипотезы, а не утверждённый макет.

Перед рисованием макетов собрать 8–12 реальных сценариев использования и референсы отдельных решений, а не копировать один браузер целиком. Проверить компактный и широкий экран, светлую и тёмную темы, длинные названия вкладок, много вкладок, увеличение текста, управление без мыши. Для большого числа вкладок проверить горизонтальную прокрутку, поиск или список вкладок, сохраняя вкладки сверху. Отдельно показать пустые, ошибочные и загружающиеся состояния.

Критерий: дизайн должен помогать читать и управлять браузером. Декоративные градиенты, случайные стеклянные панели и анимации без пользы не добавлять.

Для каждой идеи нужен сценарий, который она упрощает, и проверка на обоих типах пользователей. Если элемент нельзя объяснить через задачу, он не попадает в макет. Референсы и вопросы для проверки собраны в [первом обзоре](experiments/2026-11-10-developer-browser-discovery.md).

Для первых двух визуальных вариантов использовать верхние вкладки и [десять проверочных задач и условия сравнения](experiments/2026-11-10-search-usage-scenarios.md). Варианты могут различаться плотностью верхней панели и способом показа рабочих контекстов. Задачи составлены по кабинетному исследованию и ещё требуют проверки с людьми.
