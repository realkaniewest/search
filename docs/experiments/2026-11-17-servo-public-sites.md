# ServoShell v0.8.0: три открытых сайта на Mac

Статус: узкий исследовательский опыт 17 ноября 2026 года. Проверено только отображение одного снимка после загрузки в headless-режиме. Ввод, поиск, рисование, сохранение, переходы и работа в обычном окне не проверены.

## Среда и метод

- macOS 27.0.1 (26A434), arm64. Объём памяти в этом запуске не записан; замеров скорости и памяти нет.
- Официальный [ServoShell v0.8.0](https://github.com/servo/servo/releases/tag/v0.8.0) из `servo-aarch64-apple-darwin.dmg`. SHA-256 образа: `bfdc69c789f4214e72955520a81a6ea20142bf1f306001f4bf478917728e9361`; перед запуском значение совпало с закреплённым в [предыдущем опыте](2026-11-10-servo-macos-v080.md). Образ подключён только для чтения.
- Для каждого URL создан отдельный временный профиль. Команда: `servoshell --headless --exit --output=<путь-к-PNG> --config-dir=<отдельный-профиль> <URL>`. Бинарник вышел с кодом 0 и создал PNG 1024×740 для каждого сайта. Снимки визуально просмотрены; временные профили после опыта удалены. Конечный URL после возможных редиректов не наблюдался.
- Сайты публичные, вход в аккаунт и личные данные не использовались. Их содержимое может измениться после даты опыта.

## Границы вывода и следующий опыт

PNG и код завершения не доказывают, что поиск Wikipedia или рисование и сохранение Excalidraw работают. Ошибка IndexedDB показывает проблему в проверенном headless-сценарии ServoShell v0.8.0, но не доказывает поведение Servo в окне или в будущем встраивании. Для сопоставления нужен отдельный Wry-прототип с теми же закреплёнными URL и видимой проверкой, а затем действия внутри сайтов. Не смешивать эти результаты с измерением скорости: режимы и доказательства отличаются.
