# Wry 0.57.1: загрузка файла на macOS

Статус: два локальных успешных прогона исследовательского прототипа, второй после независимого ревью и исправлений. Это не готовый менеджер загрузок.

## Среда и сценарий

- 7 ноября 2026 года, macOS 27.0.1, Apple Silicon, Wry 0.57.1, Tao 0.37.2, Rust 1.99.1.
- Прототип: [`prototypes/wry-download`](../../prototypes/wry-download/README.md). Страница открыта через `with_html`, без внешних ресурсов. Локальный HTTP-сервер на `127.0.0.1` ответил на `GET /download` с `Content-Disposition: attachment; filename=probe.txt` и фиксированным содержимым `Search Wry download probe\n`.
- Страница через 500 мс автоматически нажала ссылку. Обработчик начала разрешал только точный URL этого локального сервера и заменял путь назначения на новую приватную папку системного временного каталога. Обработчик Wry был настроен на отказ в разрешениях; охват системных запросов этим сценарием не проверялся.

## Наблюдения

| Проверка | Результат |
| --- | --- |
| Сборка, формат, Clippy | Прошли локально с закреплёнными зависимостями. |
| `download_started_handler` | Вызван один раз с URL локального сервера. Предложенный путь указывал на системную папку Downloads и имя `probe.txt`. |
| Выбор места сохранения | Обработчик назначил абсолютный путь во временной папке. |
| `download_completed_handler` | Вызван с тем же URL, `success=true`, `callback_path=None`. |
| Файл на диске | В обоих прогонах прочитан по ранее сохранённому выбранному пути; байты полностью совпали с тестовым содержимым. Процесс завершился с кодом 0. В итоговом прогоне временная папка после выхода удалена. |

Согласно [API Wry](https://docs.rs/wry/0.57.1/wry/struct.WebViewBuilder.html#method.with_download_completed_handler), на macOS путь в callback завершения отсутствует из-за ограничения API. [Исходный код Wry 0.57.1](https://docs.rs/crate/wry/0.57.1/source/src/wkwebview/download.rs) подтверждает передачу `None` при успехе и ошибке. Наблюдение в этом прогоне согласуется с документацией.

## Вывод и границы

Для будущего менеджера загрузок нужно хранить выбранный путь и связывать его с конкретной загрузкой до callback завершения. Этот опыт показал один успешный файл, но не проверил параллельные загрузки с одинаковым URL, отмену, ошибки записи, повтор имени файла, выбор папки пользователем, файл из внешнего сайта или безопасность скачанного содержимого. В частности, один URL не является уникальным ID загрузки; схема сопоставления ещё не выбрана. На Windows и Linux тест не проводился.

После ревью папка назначения создаётся как уникальный приватный временный каталог. Callback завершения учитывается только для ожидаемого URL; локальному серверу заданы таймауты чтения и записи. Сценарии отказа и параллельных загрузок после этих изменений отдельно не прогонялись.
