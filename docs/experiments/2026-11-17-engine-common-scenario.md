# Общая локальная страница Wry и ServoShell: первый сопоставимый сценарий

Статус: на Mac 17 ноября 2026 года проверены оба движка. В [CI PR #55](https://github.com/realkaniewest/search/actions/runs/44010592413) Wry прошёл общий локальный сценарий на macOS, Windows и Linux, ServoShell на Windows и Linux. Это исследовательская страница, а не проверка обычных сайтов или готового браузера Search. Задача [#54](https://github.com/realkaniewest/search/issues/54). Позднее [ADR 0001](../adr/0001-engine-for-first-search-window.md) выбрал Wry только для ограниченного первого окна.

## Среда и входные данные

- Mac: macOS 27.0.1, arm64; Cargo 1.99.1. Wry 0.57.1 и Tao 0.37.2 из `prototypes/wry-comparison/Cargo.lock`.
- ServoShell v0.8.0: официальный `servo-aarch64-apple-darwin.dmg`. SHA-256 файла `bfdc69c789f4214e72955520a81a6ea20142bf1f306001f4bf478917728e9361` совпал с закреплённым значением [прошлого опыта](2026-11-10-servo-macos-v080.md). Запускался бинарник из временно подключённого образа, без установки в приложения.
- Одинаковый путь `/scenario.html` и содержимое из `prototypes/engine-fixtures/comparison_server.py`. Servo использовал `http://127.0.0.1:43130/scenario.html`, Wry в автоматическом прогоне использовал случайный локальный порт. Страница после POST события `scenario-ready` ставит заголовок `Search comparison ready`. Сервер привязан к loopback и не загружает внешние ресурсы. Перед каждым движком журнал сбрасывался.
- Wry: GUI WebView с явным отказом в разрешениях; верхняя навигация ограничена исходным локальным origin; новые окна отклоняются. ServoShell: `--headless --exit --output` с отдельным временным профилем. Режимы **разные**, поэтому время запуска и память не сравнивались.

Проверки самого сервера: 6 тестов маршрутов, источника запросов, предела журнала и фиксированного содержимого загрузки; Servo-раннер: 4 теста, включая обход переменных прокси; Wry-раннер: 3 теста URL, навигации и Deny, форматирование и Clippy на Mac. Эти проверки не заменяют выполнение браузерных сценариев. Повторный прогон обоих движков прошёл после исправления правила `Sec-Fetch-Site`: Servo помечает прямую навигацию как `cross-site`; сервер принимает такой запрос только для документа `/scenario.html`, но отклоняет такую отправку событий.

## Границы вывода

Подтверждена только загрузка одной локальной страницы и выполнение её JavaScript: на локальном Mac и в CI на перечисленных ОС, в разных режимах Wry и ServoShell. Не проверены реальные сайты, авторизация, медиа, кнопки Назад/Вперёд, открытие нового окна, отправка и сохранение файлов, приватность, доступность, восстановление после сбоя и сопоставимая скорость. Одного этого результата было недостаточно для выбора Wry даже для ограниченного окна; последующие опыты и границы решения описаны в [ADR 0001](../adr/0001-engine-for-first-search-window.md).

Сервер принимает только фиксированный тестовый файл. Чужой локальный процесс может повлиять на журнал; это не защищённый источник доказательств против локального противника. Для Wry автоматический раннер использует новый случайный порт и проверяет событие вместе с заголовком. Для Servo результат включает отдельный снимок и журнал. Запуски на CI показывают работу в виртуализированной среде, а не ручную проверку на пользовательских устройствах.
