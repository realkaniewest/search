# Search: первый обзор браузеров и функций для разработчиков

Статус: исследование от 10 ноября 2026 года. Выводы ниже не являются списком готовых или обещанных функций Search.

## Подтверждённые наблюдения

- [Arc for Developers](https://arc.net/developers) описывает Spaces, Profiles и отдельный Developer Mode с быстрым доступом к DevTools. Это подтверждает наличие сценария, но не доказывает, что его интерфейс подходит Search.
- [Polypane](https://polypane.app/docs/intro-to-panes/) показывает одну страницу в нескольких размерах одновременно и синхронизирует действия. [Настройки эмуляции](https://polypane.app/docs/emulation/) позволяют менять предпочтения интерфейса, сеть и параметры устройства.
- [Firefox DevTools](https://firefox-source-docs.mozilla.org/devtools-user/) уже включает развитые инструменты отладки. Search должен сначала проверить доступ к штатным DevTools выбранного движка, прежде чем проектировать собственные аналоги.
- В [запросе пользователей Arc о множестве Spaces](https://www.reddit.com/r/ArcBrowser/comments/1qyahtf/feature_request_the_ux_for_spaces_breaks_after_10/) описана проблема навигации при большом их числе. Это один качественный сигнал, не статистика по пользователям.

## Гипотезы для проверки

| Идея | Возможная польза | Что проверить |
| --- | --- | --- |
| Боковая панель вкладок с быстрым поиском | Меньше потерь среди десятков вкладок | Читаемость длинных названий, работа с клавиатуры, цена места на узком экране |
| Пространства с явной связью с профилями | Разделение проектов и тестовых аккаунтов | Понятность модели данных, защита от переноса cookies между профилями |
| Командная строка действий | Быстрые переходы без поиска кнопок | Обнаружимость действий и отсутствие конфликта с сочетаниями сайтов |
| Режим разработчика по запросу | Дополнительные инструменты без загромождения обычного экрана | Доступность DevTools на всех ОС, сохранение состояния режима |
| Параллельные размеры страницы | Проверка адаптивной верстки | Потребление памяти, синхронизация ввода, раздельность сессий, ограничения движка |
| Быстрые переключатели темы и условий сети | Проверка частых состояний сайта | Достоверность эмуляции и одинаковое поведение на трёх ОС |

Ни одна из идей не считается уникальной: часть уже есть в других браузерах. Ценность Search нужно искать в удобной совместной работе этих функций и в проверенном поведении на трёх ОС.

## Как исследовать дальше

1. Собрать 8–12 конкретных задач от обычных пользователей и разработчиков; отделить частые задачи от редких.
2. Изучить официальные возможности Arc, Firefox, Polypane, Vivaldi, Zen и платформенных DevTools, затем добавить свежие запросы из их сообществ. Для каждого сигнала сохранить ссылку и дату.
3. Нарисовать минимум два самостоятельных варианта интерфейса Search, показать много вкладок, узкое окно, светлую/тёмную тему и режим разработки. Не копировать экран Arc целиком.
4. Проверить сценарии на макетах и ограничения через прототипы движков. Только после этого расставить приоритеты для выпусков.

## Неизвестно

Пока нет пользовательских интервью, замеров частоты задач, макетов Search или проверки этих функций в выбранном движке. Нельзя утверждать, что предложенный набор улучшит работу, будет одинаковым на всех ОС или даст прирост скорости.
