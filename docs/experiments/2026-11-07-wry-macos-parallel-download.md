# Wry 0.57.1: два скачивания одного URL на macOS

Статус: четыре успешных локальных прогона режима `--parallel` и один повторный прогон одиночного режима. Последний параллельный прогон выполнен после независимого ревью и ограничения локального сервера. Это исследовательский прототип, не схема менеджера загрузок.

## Сценарий

- 7 ноября 2026 года, macOS 27.0.1, Apple Silicon, Rust 1.99.1, Wry 0.57.1, Tao 0.37.2.
- [`prototypes/wry-download`](../../prototypes/wry-download/README.md) запущен с `--parallel`. Страница через 500 и 550 мс нажимает одну ссылку на один локальный URL `http://127.0.0.1:<случайный порт>/download`. Сервер отвечает на оба запроса одним именем `probe.txt` и одинаковыми байтами, задерживая тело ответа на 800 мс. Внешняя сеть не используется.
- Обработчик начала сохраняет два файла в разные пути нового приватного временного каталога. Обработчик завершения принимает только точный локальный URL. Оба файла читаются и сверяются с ожидаемыми байтами после второго завершения; временный каталог удаляется при выходе.

## Сырые наблюдения

Во всех четырёх прогонах порядок событий был `START 0`, `START 1`, `COMPLETE 1/2`, `COMPLETE 2/2`, затем проверка двух файлов. Оба `COMPLETE` содержали один и тот же URL, `callback_path=None` и `success=true`. Оба файла имели `matches=true`, процесс завершился с кодом 0. После третьего прогона отсутствие временного каталога проверено отдельно. Одиночный режим после изменений тоже завершился с кодом 0 и `matches=true`.

Упрощённый фрагмент журнала одного прогона, без локальных путей:

```text
START url=http://127.0.0.1:<port>/download
DESTINATION index=0 path=<temporary-directory>/probe-0.txt
START url=http://127.0.0.1:<port>/download
DESTINATION index=1 path=<temporary-directory>/probe-1.txt
COMPLETE url=http://127.0.0.1:<port>/download callback_path=None success=true
COMPLETION count=1/2
COMPLETE url=http://127.0.0.1:<port>/download callback_path=None success=true
COMPLETION count=2/2
FILE path=<temporary-directory>/probe-0.txt matches=true
FILE path=<temporary-directory>/probe-1.txt matches=true
```

## Вывод и ограничения

В доступном callback Wry для macOS нет признака, который различает эти два завершения: URL одинаковый, путь отсутствует. В этом узком случае можно дождаться двух успешных callback и проверить оба файла после них, но нельзя по одному callback достоверно сказать, какой именно файл завершился. Порядок callback в четырёх прогонах не является контрактом API. По [документации Wry](https://docs.rs/wry/0.57.1/wry/struct.WebViewBuilder.html#method.with_download_completed_handler), на macOS путь в callback завершения всегда отсутствует.

Не проверены разные размеры и содержимое двух файлов, сбои одного из них, отмена, прогресс, более двух загрузок, внешний сайт и поведение на Windows/Linux. Вопрос об идентификаторе загрузки или платформенном обходном пути остаётся открытым. Ускорение не измерялось.
