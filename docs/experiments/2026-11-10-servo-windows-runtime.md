# ServoShell v0.8.0: Windows runtime probe

Статус: подготовлен CI-опыт для [задачи #35](https://github.com/realkaniewest/search/issues/35). Реальный запуск Windows-бинарника ожидает PR и журнал CI. Это официальный ServoShell, не встраивание движка в Search.

## Зафиксированные входные данные

- [Servo v0.8.0](https://github.com/servo/servo/releases/tag/v0.8.0), коммит `4e136d8ef31b7c4748fbfac606ca463f3efd7537`, ZIP `servo-x86_64-windows-msvc.zip`, опубликованный SHA-256 `0fca2f4d7e6107304631f7b9031edf0df2c3d88e0570cd19cde1`. Локально ZIP не запускался: это проверка, которую должен выполнить `windows-2025` runner.
- [Локальная страница](../../prototypes/servo-windows-runtime/probe.html) подаётся с `127.0.0.1:43132`. JavaScript меняет серый прямоугольник на цвет `#14b8a6`.
- [Сценарий](../../prototypes/servo-windows-runtime/run.ps1) проверяет SHA-256 до распаковки и запуска, наличие `servoshell.exe`, отдельный временный профиль, GET от Servo и пиксели цвета после JavaScript. Процесс ограничен 90 секундами, job 15 минутами.

## Матрица результата

| Проверка | Результат |
| --- | --- |
| Контрольная сумма ZIP и наличие `servoshell.exe` | Ожидает CI |
| Запуск Windows-бинарника с `--headless --exit --output` | Ожидает CI |
| HTTP GET и JavaScript-отрисовка в PNG | Ожидает CI |
| UI на физическом ПК, ввод, реальные сайты, загрузки, медиа, профили | Не проверено |
| Сборка Servo из исходников и встраивание в Search | Не проверено |

PNG используется только для машинной проверки; в репозиторий не сохраняется. Скрипт пытается остановить дерево процессов и удалить временные файлы при обычном выходе, но авария runner или принудительное завершение могут помешать очистке. Даже успешный CI подтвердит только этот узкий headless-сценарий на виртуальной Windows. Скорость не измеряется.
