# Search: сценарии и сравнение решений браузеров

Статус: кабинетное исследование, 10 ноября 2026 года. Сценарии ниже составлены для проверки макетов; это не результаты интервью и не утверждённые функции Search. Частота задач и приоритеты пока неизвестны.

## Что уже есть у других

| Решение | Подтверждённая возможность | Вопрос для Search |
| --- | --- | --- |
| [Arc](https://start.arc.net/release-notes) | Исторические версии сочетали Spaces, Profiles и Developer Mode с доступом к штатным инструментам разработки | Как показать связь пространства и профиля без путаницы с данными? |
| [Vivaldi](https://help.vivaldi.com/desktop/tabs/workspaces/) | Workspaces группируют вкладки; [Tab Stacks](https://help.vivaldi.com/desktop/tabs/tab-stacks/) дают ещё один уровень группировки | Сколько уровней навигации действительно нужно? |
| [Zen](https://docs.zen-browser.app/user-manual/workspaces) | Пространства можно связать с контейнерами для разных аккаунтов | Поймёт ли пользователь, какие данные разделены, а какие общие? |
| [Polypane](https://polypane.app/docs/intro-to-panes/) | Несколько размеров одной страницы с синхронным взаимодействием | Нужен ли отдельный режим, если штатный DevTools уже решает задачу? |
| [Firefox](https://firefox-source-docs.mozilla.org/devtools-user/responsive_design_mode/index.html) и [Chrome](https://developer.chrome.com/docs/devtools/device-mode/) | Штатные инструменты имитируют размеры и свойства устройств; Chrome прямо описывает это как приближение, а не реальное устройство | Какие задачи останутся неудобными после доступа к штатным DevTools? |
| [Chrome DevTools](https://developer.chrome.com/docs/devtools/overrides) | Локальные подмены ресурсов и заголовков ответа | Есть ли смысл повторять зрелый инструмент внутри интерфейса Search? |

Из этих источников не следует, что Search сможет предоставить одинаковые возможности на macOS, Windows и Linux: это зависит от выбранного движка и его API.

На 10 ноября 2026 года [Arc объявил](https://resources.arc.net/hc/en-us/articles/44412972248471-Arc-Sunset-Key-Dates-and-What-to-Expect), что его версии для macOS и Windows прекратят работу 22 декабря 2026 года. Поэтому Arc остаётся историческим примером интерфейса, но не ориентиром по долгосрочной поддержке. Для Search отдельно проверить экспорт пользовательских данных и работу без обязательного аккаунта; решение об аккаунте пока не принято.

## Прямые сигналы из сообществ

Это отдельные сообщения, а не опрос или оценка распространённости проблемы.

- Пользователь [Arc](https://www.reddit.com/r/ArcBrowser/comments/1qyahtf/feature_request_the_ux_for_spaces_breaks_after_10/) описывает, как становится трудно находить нужное пространство среди примерно 20. Проверять вариант списка с названиями, а не только значками.
- В другом [обсуждении Arc](https://www.reddit.com/r/ArcBrowser/comments/1xd7tdc/which_browser_handles_profiles_and_spaces_the_way/) пользователь ищет независимую связь пространств и профилей, чтобы не входить в одни аккаунты повторно.
- В [Zen issue #7976](https://github.com/zen-browser/desktop/issues/7976) сообщают о конфликте сочетания для split view с просмотром исходника. [Запрос #14425](https://github.com/zen-browser/desktop/discussions/14425) просит переносить вкладку в пространство с клавиатуры.
- В [Zen issue #11851](https://github.com/zen-browser/desktop/issues/11851) описано медленное переключение пространств с множеством закреплённых вкладок на одной конфигурации Windows. Это сигнал для измерений, не доказательство общей проблемы Zen.

## Десять задач для первых макетов

Обозначения: О — обычное использование; Р — разработка. Эти задачи нужно проверить с реальными людьми, прежде чем назначать им приоритет.

| № | Задача человека | Что должен показать макет |
| --- | --- | --- |
| 1 · О | Открыть сайт по адресу, затем найти информацию поиском | Понятная адресная строка и различие адреса и запроса |
| 2 · О | Найти одну вкладку среди 30 открытых | Поиск, читаемые названия и ясная активная вкладка |
| 3 · О | Вернуться к вчерашней странице после перезапуска | Доступ к истории, восстановленной сессии и закладкам без смешения понятий |
| 4 · О | Скачать файл и понять, куда он попал | Видимое состояние загрузки, ошибки и конечное расположение |
| 5 · О | Открыть личный сайт отдельно от рабочего и затем приватное окно | Видимые границы профиля и приватного режима |
| 6 · Р | Найти вкладку локального проекта и открыть DevTools | Быстрый переход к проекту и штатным инструментам движка |
| 7 · Р | Проверить сайт с двумя тестовыми аккаунтами | Ясный выбор профиля без случайного переноса cookies |
| 8 · Р | Сравнить узкий и широкий размер одной страницы | Доступный способ сравнения и честное обозначение эмуляции |
| 9 · Р | Проверить тёмную тему, reduced motion и состояние без сети | Быстрый доступ к настройкам или DevTools без постоянных кнопок на обычном экране |
| 10 · Р | Передать коллеге ссылку и описание сбоя | Отдельные действия для точного локального URL и очищенного варианта без токенов |

## Проверка двух вариантов интерфейса

Сделать два оригинальных макета на одной сетке сценариев: (А) постоянная боковая навигация с компактной строкой адреса, (Б) обычные вкладки с раскрываемой панелью проектов. Это варианты для проверки, не утверждённый дизайн. Не переносить внешний вид Arc и не добавлять инструменты разработчика на главный экран без нужды.

Для каждого варианта показать задачи 2, 5, 6, 7 и 8; узкое и широкое окно; 1, 5 и 20 пространств; длинные названия; светлую и тёмную темы; крупный текст; управление только клавиатурой. Записать время и ошибки выполнения, неверные ожидания о профилях, обнаружимость DevTools и число действий. До проверки не объявлять победителя по вкусу команды.

## Ограничения и следующая проверка

- Интервью и реальные сессии с пользователями ещё не проведены. Кабинетные сценарии нельзя выдавать за подтверждённые потребности.
- Нужно проверить доступность DevTools и эмуляции у выбранного движка отдельно на каждой ОС. Поведение имитации не заменяет тест на реальном устройстве.
- Модель пространств и профилей потребует отдельной проверки хранения, разрешений и удаления данных. Переключение между десятками вкладок нужно измерять, а не называть быстрым заранее.
- Перед макетами составить таблицу сочетаний клавиш с учётом ОС, DevTools и сайтов. Для опасных действий нужен предсказуемый способ отмены.
