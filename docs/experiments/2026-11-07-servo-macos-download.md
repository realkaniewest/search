# Servo 0.7.0: локальная загрузка в ServoShell на macOS

Статус: два запуска официального ServoShell. В этом узком сценарии скачивание файла не наблюдалось. Это не проверка встроенного Servo в Search и не вывод обо всех версиях Servo.

## Среда и входные данные

- 7 ноября 2026 года, macOS 27.0.1, Apple Silicon, Servo v0.7.0 из [официального выпуска](https://github.com/servo/servo/releases/tag/v0.7.0), коммит `aac43a3f31a259f04a574f5ec4e959c943ad7cc7`. Использован ранее скачанный и проверенный по SHA-256 образ; см. [первый smoke](2026-11-06-servo-macos-release-smoke.md).
- Временный локальный HTTP-сервер на `127.0.0.1:43129`. Страница `/page` через 1 секунду нажимает ссылку на `/download`. Ответ `/download`: статус 200, `Content-Type: application/octet-stream`, `Content-Disposition: attachment; filename="search-servo-v070-probe.txt"`, тело `Search Servo download probe\n`. Воспроизводимый сервер добавлен в [`prototypes/engine-fixtures/download_server.py`](../../prototypes/engine-fixtures/download_server.py). Во время самого прогона использовалась временная версия: ответ `/download` и автоматический переход совпадают, но форматирование HTML страницы `/page` отличается.
- ServoShell запущен непосредственно из подключённого образа с `--config-dir=/private/tmp/search-servo-download-profile` и URL `http://127.0.0.1:43129/page`. Личные аккаунты и внешние сайты не использовались.

## Наблюдения

| Проверка | Результат |
| --- | --- |
| Запрос страницы и файла | В обоих запусках локальный сервер записал `GET /page` 200 и `GET /download` 200. |
| Интерфейс ServoShell | После автоматического перехода адресная строка показывала `/download`; на странице был текст `Unknown content type (application/octet-stream)`. Первый запуск проверен снимком экрана. |
| Ожидаемый файл | Файл `search-servo-v070-probe.txt` не найден ни в `~/Downloads`, ни в указанном каталоге конфигурации после обоих запусков. Поиск по всему диску не проводился. |
| Лог ServoShell | В обоих запусках было предупреждение `unknown completed load PageSource("http://127.0.0.1:43129/download")`. |
| Завершение | Оба процесса остановлены `Ctrl-C` с кодом 130. Локальный сервер остановлен, образ отключён. |

После записи fixture в репозиторий его `/page` и `/download` проверены через `curl`: статус 200, нужные `Content-Type`, `Content-Disposition`, длина 28 байт и ожидаемое тело. Отдельное зависшее соединение прервалось по двухсекундному таймауту. Эти проверки относятся к серверу; ServoShell с сохранённой копией fixture повторно не запускался.

Текст `Unknown content type` соответствует [ветке обработки неизвестного MIME-типа в Servo v0.7.0](https://github.com/servo/servo/blob/v0.7.0/components/script/dom/servoparser/mod.rs). Это согласуется с наблюдаемой страницей, но само по себе не доказывает отсутствие отдельного механизма загрузок во всех оболочках Servo.

## Вывод и границы

В этом опыте ServoShell 0.7.0 получил attachment-ответ, но не показал сохранённый файл в проверенных местах и отобразил страницу неизвестного типа. Для Search это незакрытый сценарий скачивания. В [Wry 0.57.1 на том же Mac](2026-11-07-wry-macos-download.md) локальный attachment сохранился, но тестовые страницы и бинарные артефакты двух опытов не были полностью одинаковыми. Это качественное сравнение поведения, не измерение скорости и не окончательный выбор движка.

В [следующем опыте](2026-11-07-servo-macos-manual-download.md) проверен обычный клик по той же ссылке в сохранённом fixture. В рамках этого первоначального опыта не проверялись другой MIME-тип, файл с внешнего сайта, выбор папки, ошибка сохранения, загрузка через встроенный Servo, Windows и Linux. Новый выпуск Servo нужно проверять отдельно.
