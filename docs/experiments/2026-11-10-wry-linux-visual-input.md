# Wry 0.57.1: пиксели и ввод под Linux Xvfb

Статус: исследовательский прототип прошёл автоматическую проверку на Ubuntu 24.04 в виртуальном X11-экране. Проверены пиксели конкретной области страницы и доставка клика с вводом текста до JavaScript. Это не проверка физического дисплея, Wayland или качества интерфейса.

## Среда и процедура

- 10 ноября 2026 года, GitHub Actions `ubuntu-24.04`, Xvfb 1280×800×24, Wry 0.57.1, Tao 0.37.2, Rust 1.99.1. [CI job PR #27](https://github.com/realkaniewest/search/actions/runs/42739363748/job/129576338849).
- Код: [`prototypes/wry-linux-runtime`](../../prototypes/wry-linux-runtime/README.md). Сохранился прежний smoke-сценарий с локальным HTML и точным маркером изменения заголовка.
- Новый opt-in режим держит окно открытым после первого маркера. Скрипт находит окно через `xdotool`, снимает его через ImageMagick `import`, считает пиксели точного цвета `#14B8A6` и требует более 10 000. Затем отправляет X11 клик в большую кнопку и вводит фиксированную строку. JavaScript выставляет второй точный заголовок только если произошли оба действия; Rust завершает процесс с кодом 0 только при его получении. При обычном завершении скрипт удаляет временный PNG и журнал через `EXIT`-обработчик.

Журнал содержит предупреждения об отсутствующем `org.a11y.Bus` и о DRI3/ускорении `libEGL`. Они не остановили сценарий. Доступность и аппаратное ускорение здесь не оценивались. Большая часть 14 минут 42 секунд Linux job пришлась на установку пакетов и сборку; это не время работы браузера.

## Границы

Тест подтверждает, что WebKitGTK нарисовал ожидаемую одноцветную область в окне Xvfb и страница получила клик и текстовый ввод через X11. Он не измеряет качество шрифтов, стабильность сложных сайтов, скорость на устройстве, доступность, Wayland, профиль, разрешения, загрузки, медиа или работу на пользовательском дистрибутиве. Для этих пунктов нужны отдельные проверки. Архитектура Search ещё не выбрана.
