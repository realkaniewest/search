# Wry: реальный запрос камеры на macOS

Статус: опыт не подтвердил вызов обработчика Wry. Владелец отклонил системный запрос macOS, страница получила отказ, а обработчик Wry не вызвался. Точный порядок внутренних проверок не наблюдался, поэтому результат проверки `Deny` остаётся неопределённым.

## Среда и сценарий

- 7 ноября 2026 года, macOS 27.0.1, Apple Silicon, Wry 0.57.1, Tao 0.37.2, Rust 1.99.1.
- Исходники опыта: [`prototypes/wry-permission-deny/`](../../prototypes/wry-permission-deny/README.md).
- Приложение поднимает страницу на случайном порту `127.0.0.1` и использует приватный WebView. Страница автоматически вызывает `getUserMedia({video:true})`. Обработчик Wry при вызове считает запросы `Camera` и отвечает `Deny`. Страница сообщает имя ошибки локальному серверу; программа принимает успех только при `NotAllowedError` **и** ненулевом счётчике обработчика.

## Наблюдения

| Проверка | Результат |
| --- | --- |
| Сборка и Clippy | Проходит локально. |
| Диагностический unit-тест | Проходит: `NotAllowedError` без вызова обработчика не считается успехом. |
| Первый запуск страницы | `NotAllowedError`, `camera handler calls: 0`, код выхода 1. Владелец Mac сообщил, что отклонил системный запрос камеры. |
| Второй запуск с подробной диагностикой | `NotAllowedError`, `camera handler calls: 0`, код выхода 1. Страница сообщила `secure=true`, API `mediaDevices.getUserMedia` присутствует. |
| Финальная версия парсера результата | Unit-тест проходит. Повторный запрос камеры после его исправления не запускался, чтобы не тревожить владельца новым системным запросом. |
| Запуск без ключа `--request-camera` | Завершается с кодом 1 до создания локального сервера и окна; нового запроса камеры нет. |

После отказа в системном запросе мы не увидели вызова обработчика Wry. Возможно, системная проверка остановила запрос раньше, но это не доказано. Мы не меняли настройки приватности Mac и не предоставляли доступ камере. Результат нельзя записывать как «Wry отклонил запрос» или «Wry не работает». Нужен отдельный контролируемый опыт с согласованным системным доступом либо другой способ наблюдать delegate без обращения к реальной камере.

Этот диагностический бинарник не запускается в CI: системный запрос нельзя корректно разрешить автоматически. CI проверяет формат, Clippy, сборку и логику оценки результата. Вопрос origin-aware разрешений остаётся открытым; см. [аудит API Wry](2026-11-06-wry-permissions-audit.md).
