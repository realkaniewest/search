# Wry smoke на macOS, 6 ноября 2026 года

Статус: локальная сборка и ручной smoke-проход финальной версии выполнены. Это не тест браузера Search и не сравнение скорости.

После этого прогона в прототип добавлен явный отказ в обработчике разрешений. Новая версия прошла unit-тест, Clippy и сборку, но окно с запросом разрешения вручную ещё не проверялось. См. [аудит API](2026-11-06-wry-permissions-audit.md).

## Среда

- macOS 27.0.1, arm64, Mac17,3, 16 GiB RAM.
- Rust 1.99.1, Wry 0.57.1, Tao 0.37.2.
- Xcode Command Line Tools доступны.
- Исходники: `prototypes/wry-smoke/`, зависимости зафиксированы в `Cargo.lock`.

## Сценарий

1. Выполнить `cargo run --locked --manifest-path prototypes/wry-smoke/Cargo.toml` из корня проекта.
2. Проверить одно окно с заголовком `Search: Wry smoke test`, русским текстом и ссылкой.
3. Нажать ссылку и проверить переход на `https://www.rust-lang.org/`.
4. Закрыть окно и проверить завершение процесса.

## Ограничения

Статическая страница `with_html` имеет null origin по [документации Wry](https://docs.rs/wry/latest/wry/struct.WebViewBuilder.html). Режим `with_incognito(true)` включён, но удаление данных и изоляция профилей здесь не проверены. Навигация после фиксированной ссылки не ограничена политикой Search. Сырых измерений производительности и сравнений с другими браузерами нет.

Первый ручной проход был сделан до добавления `with_incognito(true)` и замены ссылки на сайт Rust. Финальная сборка повторно проверена вручную. Сбой в ограниченной графической среде нужно учитывать при автоматизации UI-тестов; причина связана с отсутствием доступного `NSScreen` в том запуске, но точная граница среды отдельно не изолирована.
