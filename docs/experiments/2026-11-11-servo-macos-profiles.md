# ServoShell v0.8.0: изоляция профилей на Mac

Статус: два независимых запуска и финальный контрольный прогон воспроизводимого опыта для [задачи #39](https://github.com/realkaniewest/search/issues/39). Проверялся официальный ServoShell v0.8.0 на одном Mac и одном локальном HTTP origin. Это не проверка встроенного движка Search.

## Основание для опыта

В [исходниках Servo v0.8.0](https://github.com/servo/servo/blob/v0.8.0/ports/servoshell/prefs.rs#L681-L690) есть `--config-dir`. Отдельный [`--temporary-storage`](https://github.com/servo/servo/blob/v0.8.0/ports/servoshell/prefs.rs#L540-L542) передаётся не во все подсистемы хранения; [WebStorage](https://github.com/servo/servo/blob/v0.8.0/components/storage/storage_thread.rs#L48-L62) получает каталог конфигурации. Поэтому отсутствие сохранения cookie и `localStorage` нельзя выводить из названия флага. [Сообщение upstream](https://github.com/servo/servo/issues/46961) описывает риск на более старом коммите и служит гипотезой, а не результатом для v0.8.0.

## Сценарий

- [Прототип](../../prototypes/servo-mac-profiles/README.md) использует тестовые `A_test`, `B_test`, `P_test` на одном HTTP origin `127.0.0.1` со свободным портом, только в текущем процессе сервера.
- Перед записью идут зелёная и красная контрольные страницы без cookie и `localStorage`: обычная таблица с двумя большими цветными ячейками и видимым заголовком. Первая открывается без query URL. Их фактические пиксели калибруют проверку из-за отличий цветопередачи PNG. Если снимок белый, серый или неизвестного цвета, тест сохраняет его в отдельном временном каталоге и выводит число запросов GET, размер PNG и последние строки журнала Servo без query URL. Из такого снимка нельзя делать вывод об изоляции профилей.
- Каталоги A и B запускаются раздельно: запись и повторное чтение после завершения основного процесса ServoShell. B до записи должен быть пуст; A после записи B должен сохранить своё значение.
- Каталог P запускается с `--temporary-storage`: сначала проверяется пустое состояние, затем запись. После записи P повторно читаются A и B, чтобы поймать перенос данных. Список имён и размеров файлов снимается после завершения основного процесса ServoShell; потомки отдельно не отслеживаются. После перезапуска P проверяется ожидание пустого значения и отдельно ожидание `P_test`. Содержимое файлов не выводится; наличие вымышленной метки в начале файла отмечается отдельно.
- Каждое PNG делится на две половины: cookie слева, `localStorage` справа. Зелёный означает совпадение с ожидаемым значением, красный — несовпадение. В выводе они считаются отдельно.

## Результат двух запусков

Обе контрольные страницы отрисовались. Фактический зелёный цвет на Mac был `00C2B5`, красный `E53D31` в обоих прогонах. Таблица ниже показывает cookie и `localStorage` отдельно. `pass` означает совпадение с ожидаемым значением конкретного шага, `fail` означает несовпадение.

| Шаг | Повтор 1: cookie / localStorage | Повтор 2: cookie / localStorage |
| --- | --- | --- |
| A_set, записать `A_test` | pass / pass | pass / pass |
| B_empty, B до записи пуст | pass / pass | pass / pass |
| B_set, записать `B_test` | pass / pass | pass / pass |
| A_reopen, A сохранил `A_test` | pass / pass | pass / pass |
| B_reopen, B сохранил `B_test` | pass / pass | pass / pass |
| P_empty, P до записи пуст | pass / pass | pass / pass |
| P_set, записать `P_test` | pass / pass | pass / pass |
| A_after_P, A не получил P | pass / pass | pass / pass |
| B_after_P, B не получил P | pass / pass | pass / pass |
| P_reopen_empty, P после перезапуска пуст | **fail / fail** | **fail / fail** |
| P_reopen_P, P после перезапуска читает `P_test` | pass / pass | pass / pass |

После `P_set` в двух первых прогонах найден `cookie_jar.json` размером 525 байт с вымышленной меткой `P_test`, `localstorage.json` размером 110 байт и файлы SQLite для webstorage. После каждого из этих прогонов `pgrep -fl servoshell` не нашёл процессов с этим именем.

Финальный контрольный прогон уже выполнен после исправления общего условия. Все проверки A/B снова дали true. `P_reopen_empty` дал fail/fail, а `P_reopen_P` pass/pass. Машинно читаемый `verdict.all_probe_criteria_pass` был false; процесс завершился с кодом 2. Это ожидаемое обнаружение несоответствия критерию, а не сбой запуска или отрисовки.

## Вывод и границы

На этом Mac в ServoShell v0.8.0 профили A/B прошли проверку разделения cookie и `localStorage`, включая повторный запуск. Флаг `--temporary-storage` **не прошёл наш критерий приватности**: P после перезапуска вернул оба значения, а тестовая cookie осталась в файле. Скрипт выводит машинно читаемый `verdict`: код выхода 0 возможен, только когда одновременно истинны `A_B_cookie_checks_pass`, `A_B_localStorage_checks_pass` и `temporary_storage_meets_probe_criterion`. Иначе `all_probe_criteria_pass` ложно и код выхода равен 2. Логику общего условия проверяет отдельный регрессионный тест. Финальный прогон подтвердил ожидаемый код 2 при провале P.

Результат нельзя переносить на все версии Servo, способы встраивания или ОС. Тест не проверяет cache, IndexedDB, историю, разрешения, одновременные окна и аварийное завершение. Сканирование первых 2 MiB не доказывает отсутствия иных следов. `pgrep` по имени `servoshell` не исключает потомков с другим именем. Успех будущего запуска этого сценария сам по себе тоже не докажет готовность полноценного приватного режима.
