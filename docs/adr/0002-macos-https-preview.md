# ADR 0002: экспериментальная HTTPS-навигация на macOS

Статус: предложено. До принятия действует ограничение [ADR 0001](0001-engine-for-first-search-window.md).

## Решение

Разрешить внутреннее HTTPS-превью Search для macOS с WKWebView через Wry 0.57.1. Превью помечается в интерфейсе, доступно только в сборке для разработки и включается явно при запуске. В нём доступны HTTPS-навигация, поиск, вкладки, история, закладки и восстановление сеанса. Обычная сборка и остальные ОС продолжают действовать в рамках ADR 0001.

Это предложение отделяет проверку интеграции macOS от выбора движка для выпуска. Пункты 1–3 ADR 0001 по сравнению движков и производительности отложены только для этого локального эксперимента. Проверка SmartScreen на физическом ПК остаётся условием включения режима на Windows. Существующие сравнения измеряли разные режимы и не устанавливают преимущество в скорости.

## Границы

- Применять одну политику верхней навигации к вводу, ссылкам, перенаправлениям, истории и восстановлению вкладок. Канонизировать адрес штатным парсером URL, требовать HTTPS и отклонять учётные данные, неявные схемы и порт кроме стандартного. Отдельно проверять текст поля и фактический переход. В закреплённой версии Wry ответ WKWebView не проходит тот же фильтр, что действие навигации. Если редирект нельзя отклонить до показа документа, режим остаётся закрытым.
- В обычном HTTPS-превью отклонять явные локальные имена и IP-литералы в верхней навигации. Отдельное окно разработки принимает адреса loopback и удерживает переходы в пределах выбранной схемы, хоста и порта. Инспектор доступен в этом окне. DNS и субресурсы остаются под управлением WebKit, поэтому эти правила ограничивают верхнюю навигацию.
- Для обычных вкладок использовать один локальный профиль. Сеанс, история и закладки хранятся локально. На macOS 14 и новее допускается постоянное хранилище данных сайтов после проверки изоляции. Приватное окно и окно разработки получают временные данные сайтов, отдельные от обычного профиля. Эти окна не сохраняют обычную историю, закладки или сеанс.
- IPC и внутренние команды доступны только панели. Отклонять переданные Wry запросы чувствительных разрешений, автоматические загрузки со страниц, новые окна и внешние схемы. Проверять отказ геолокации отдельно, поскольку этот запрос не передаётся через штатный обработчик Wry на macOS. Проверка сертификатов остаётся включённой.
- Передавать странице только файлы, подтверждённые пользователем в системном NSOpenPanel. Ручная загрузка по прямому публичному HTTPS-адресу начинается после подтверждения пути в NSSavePanel. Запрещать перезапись существующего файла, удалять частичные данные после отмены и добавлять метку карантина macOS перед завершением загрузки.

## Наблюдения и приёмка

На Mac в Search выполнен поиск Rust внутри Wikipedia с возвратом назад. В двух локальных прогонах тестовые вкладки остались на исходной странице после автоматических попыток открыть временный файл и незарегистрированную схему. При отдельном клике по ссылке на Системные настройки Search остался на странице, диалога не было, процесс настроек не запустился. Покрытие ограничено наблюдавшимися сценариями. [PR #92](https://github.com/realkaniewest/search/pull/92).

На macOS 27.0.1 HTTPS-превью загрузило конечный документ после редиректа HTTPS → HTTPS, однократно заблокировало проверенный переход HTTPS → HTTP и не загрузило сайт с самоподписанным сертификатом. После таймаута та же вкладка открыла доверенный сайт. Запросы камеры, микрофона и геолокации завершились отказом в проверенных сценариях. Для микрофона подтверждён вызов обработчика Search, для геолокации наблюдался отказ со стороны WebKit.

В интерфейсе сборки с системными листами подтверждены успешное сохранение тестового RFC с карантином и получение локальной страницей ровно одного выбранного файла с ожидаемым содержимым. Отмена выбора дала ноль файлов. [PR #105](https://github.com/realkaniewest/search/pull/105).

Перед передачей экспериментальной сборки:

1. В новом режиме открыть по полному адресу минимум два HTTPS-сайта вне старого списка. Проверить действие внутри сайта, переключение вкладок, возврат назад и канонический адрес после редиректа.
2. Повторить проверку границ с реально включённой политикой нового режима. Проверить чувствительные разрешения, автоматические загрузки, новые окна, отсутствие IPC у страницы, локальные файлы и внешние схемы. Для системных листов проверить подтверждение и отмену, для ручной загрузки проверить карантин и сохранность существующего файла. С временными метками проверить совместное хранение между обычными вкладками и изоляцию от приватного окна и окна разработки. После перезапуска подтвердить восстановление обычного сеанса и отсутствие временных данных.
3. Проверить URL и редиректы на локальной тестовой оснастке либо на заранее утверждённых адресах. Проверить отклоняемый переход из адресного поля и со страницы через редирект, а также отказ при недействительном TLS-сертификате. Отдельно проверить, что стандартный запуск остаётся ограниченным и что переключатель не включает режим на Windows или Linux.
4. Получить независимое QA и security-ревью фактического diff и результатов. Если границу нельзя подтвердить, оставить эксперимент локальным и ограниченным.
