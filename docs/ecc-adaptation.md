# Что Search взял из ECC

Посмотрели [ECC](https://github.com/affaan-m/ECC), его [настройку Codex](https://github.com/affaan-m/ECC/tree/main/.codex) и [описание процесса ревью](https://github.com/affaan-m/ECC/blob/main/workflows/README.md). Взяли идеи процесса и написали свои инструкции под браузер Search. Код, готовые команды и тексты ECC в проект не копировали.

| Идея ECC | Как применена в Search |
| --- | --- |
| Отдельные роли для поиска фактов и ревью | Проектные роли `researcher`, `implementer`, `qa_reviewer`, `security_reviewer` в `.codex/agents/` |
| Короткий контекст для каждой задачи | `docs/task-template.md` задаёт результат, владельца файлов, источники и способ проверки |
| Независимые измерения ревью | Поведение и безопасность проверяют разные роли, когда затронуты соответствующие области |
| Проверка серьёзных замечаний | Повторяющиеся замечания объединяются, спорные проверяются воспроизведением; сбой ревью не считается одобрением |
| Проверяемый результат | Шаблон `.github/PULL_REQUEST_TEMPLATE.md` фиксирует проверки по ОС, неизвестное и известные риски |

Пока не подключаем установщик ECC, сторонние сервисы, MCP-серверы, большой набор команд и фоновые циклы. Они добавили бы зависимости и полномочия, которые не нужны на исследовательском этапе. Хуки Claude Code не являются настройкой Codex. Когда появится код, можно отдельно оценить автоматические проверки по конкретному риску.

ECC распространяется под [MIT](https://github.com/affaan-m/ECC/blob/main/LICENSE). Для Search владелец выбрал [MPL-2.0](../LICENSE); выбор независим от ECC.
