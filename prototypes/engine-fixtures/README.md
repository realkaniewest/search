# Локальные страницы для сравнения движков

Запуск из корня проекта:

```sh
python3 -m http.server 43128 --bind 127.0.0.1 --directory prototypes/engine-fixtures
```

Откройте `http://127.0.0.1:43128/basic.html`. Страница не загружает внешние ресурсы и не содержит личных данных. После нажатия кнопки заголовок вкладки меняется с `Search fixture: ready` на `Search fixture: clicked`.

Для отдельной проверки скачивания запустите `python3 prototypes/engine-fixtures/download_server.py` из корня проекта и откройте `http://127.0.0.1:43129/page`. Страница через секунду нажмёт ссылку на `/download`. Сервер отдаёт фиксированный файл с `Content-Disposition: attachment` и именем `search-servo-v070-probe.txt`. Перед повтором проверьте, нет ли такого файла в папке загрузок. Сервер слушает только `127.0.0.1`; остановка через `Ctrl-C`.

Для проверки настоящего клика откройте `http://127.0.0.1:43129/manual`: это та же ссылка без автоматического JavaScript-нажатия. Нажмите `Download test file` в окне проверяемого движка.

## Единый локальный сценарий для Wry и Servo

Запустите отдельный сервер из корня проекта:

```sh
python3 prototypes/engine-fixtures/comparison_server.py
```

Он слушает только `127.0.0.1:43130`, не отдаёт произвольные файлы и не обращается к внешним сайтам. Перед каждым движком сбросьте журнал отдельной командой `curl -X POST --data '' -H 'X-Search-Fixture-Control: 1' http://127.0.0.1:43130/reset`. Если сервер работает, `http://127.0.0.1:43130/health` возвращает `ready`. После действий откройте `http://127.0.0.1:43130/events`: там только имена событий, пути разрешённых страниц, размер и SHA-256 **только точного тестового файла**, без его содержимого. Чужой файл сервер отклоняет до записи хеша. Журнал ограничен 256 событиями; при переполнении запрос получает ошибку и перед новым опытом нужен сброс.

Сервер отклоняет чужой `Host` и межсайтовые POST; заголовки CSP запрещают встраивать страницы в чужой сайт. Это защита целостности локального опыта, но не аутентификация: другой локальный процесс всё ещё может обратиться к `127.0.0.1` и повлиять на журнал. Для автоматического Wry-опыта используется новый случайный порт; перед каждым опытом журнал сбрасывается. Не использовать журнал как доказательство против злонамеренного локального процесса.

Для автоматической проверки загрузки страницы откройте `/scenario.html`: после успешного JavaScript POST `/event` страница устанавливает заголовок ровно `Search comparison ready`, текст `Сценарий готов` и `data-ready="true"` у `body`. В журнале должно быть `scenario-ready`. Это проверяет только загрузку и локальный JavaScript, не работу обычных сайтов.

| Действие | Адрес и ожидаемый факт |
| --- | --- |
| Навигация | Открыть `/start`, нажать «Перейти на вторую страницу», затем Назад и Вперёд. В окне должны появиться страницы start, second, start, second. Журнал отмечает запросы страниц и `start-loaded`/`second-loaded`. Кэш и восстановление могут менять число запросов, поэтому только по журналу не делать вывод о кнопках Назад/Вперёд. |
| Новое окно | На `/start` нажать «Открыть новое окно». Ожидать `/popup` в новом окне или вкладке и события `popup-clicked`, `popup-loaded`. Журнал `popup-loaded` сам по себе не показывает, где именно открылась страница: это проверяется в GUI. |
| Скачивание | На `/download-page` нажать ссылку. Сервер отмечает `download-request` и отдаёт `search-comparison.txt` с `Content-Disposition: attachment`; SHA-256 файла должен совпасть с SHA-256 строки `Search engine comparison fixture v1` с переводом строки. Запрос ещё не доказывает сохранение файла: проверить конечный файл и место отдельно. |
| Отправка файла | На `/upload-page` выбрать `upload-sample.txt` из этой папки и нажать «Отправить». Результат показывает размер и SHA-256; журнал содержит событие `upload`. Это проверяет выбор файла и отправку, если действие сделано в GUI. |

`/basic.html` доступен и через этот сервер. Старые серверы на портах 43128 и 43129 остаются для прежних опытов. Этот набор не проверяет медиа, камеру, микрофон, печать, авторизацию, реальные сайты, изоляцию профилей, сбои или скорость. Их результаты записываются отдельно; не подменяйте их успешными локальными событиями.

Проверка самих маршрутов и журнала:

```sh
python3 -m unittest discover -s prototypes/engine-fixtures -p 'test_comparison_server.py'
```
