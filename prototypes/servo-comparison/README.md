# ServoShell: одинаковая локальная страница

Это исследовательский запуск официального ServoShell v0.8.0 на странице из `prototypes/engine-fixtures`. Скрипт не скачивает и не устанавливает ServoShell. Перед запуском отдельно проверьте версию и SHA-256 бинарного выпуска по официальной странице Servo. Версию переданного бинарника сам скрипт **не проверяет**.

1. Запустите сервер тестовых страниц согласно `prototypes/engine-fixtures/README.md`. Он должен слушать только `127.0.0.1:43130`.
2. Запустите на macOS или Linux:

   ```sh
   python3 prototypes/servo-comparison/run.py --binary /absolute/path/to/servoshell
   ```

   На Windows:

   ```powershell
   python prototypes/servo-comparison/run.py --binary C:\path\to\servoshell.exe
   ```

Скрипт сбрасывает журнал локального сервера, запускает ServoShell с отдельным временным профилем и `--headless --exit --output`, затем проверяет код завершения, PNG и событие `scenario-ready`. Печатает размер и SHA-256 снимка. Временный профиль и снимок удаляются после проверки. Не запускайте несколько экземпляров параллельно на одном сервере: `/reset` и `/events` общие. Используется только локальный HTTP-адрес; другой адрес скрипт отклонит.

Что это доказывает: переданный ServoShell загрузил локальную страницу, выполнил её JavaScript до маркера и создал PNG. Это **не** проверка настоящего окна, кликов, вкладок, всплывающих окон, загрузки файлов, медиа, разрешений, профилей браузера или скорости. Значения SHA-256 нужны для фиксации результата, а не для оценки качества изображения. Для одинакового сравнения с Wry нужен отдельный протокол на той же версии страниц и ОС.

Проверки самого скрипта без ServoShell:

```sh
python3 -m unittest discover -s prototypes/servo-comparison -p 'test_*.py'
```
