# Wry: сравнение на общей локальной странице

Исследовательский прототип открывает только HTTP-страницу на loopback IP и ждёт заголовок `Search comparison ready`. Это проверка загрузки локальной страницы и выполнения JavaScript в Wry 0.57.1, а не полноценный браузер Search.

Из корня проекта сначала запустите сервер `python3 prototypes/engine-fixtures/comparison_server.py`. В другом терминале запустите `cargo run --locked --manifest-path prototypes/wry-comparison/Cargo.toml`. По умолчанию откроется `http://127.0.0.1:43130/scenario.html`; при необходимости передайте другой локальный URL первым аргументом после `--`. Ожидается `PASS` и завершение программы. Отдельно сравните записанные сервером события. Код 1 означает таймаут или закрытие окна до готовности, код 2 означает некорректный URL или аргументы.

Прототип создаёт один WebView во временном хранилище, отклоняет все разрешения, переданные Wry, переходы **верхней страницы** за пределы исходного локального origin и запросы нового окна. Это не доказывает блокировку подресурсов или сетевых запросов страницы к другим локальным службам; тестовая страница не содержит таких запросов. На Windows он переопределяет дополнительные аргументы WebView2 пустой строкой, чтобы не использовать аргумент Wry 0.57.1, отключающий SmartScreen по умолчанию. Фактическая работа SmartScreen здесь не проверяется. Внешние страницы, `window.open`, загрузки, выбор файла, навигация назад/вперёд, профили, IPC, доступность и рендеринг пикселей этим запуском не проверяются. Не использовать его для личных аккаунтов.

Сборка и тесты требуют Rust 1.99.1 и системных библиотек Wry на соответствующей ОС. На macOS 27.0.1 Apple Silicon прошли сборка, три модульных теста и запуск окна с общей локальной страницей; окно само завершилось после заголовка готовности, а сервер записал `request /scenario.html` и `scenario-ready`. Результаты запуска фиксируются отдельно в `docs/experiments/` с версией ОС и движка.
