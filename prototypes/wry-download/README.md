# Wry download probe

Узкий исследовательский опыт для macOS. Это не менеджер загрузок Search.

Запуск из корня репозитория: `cargo run --locked --manifest-path prototypes/wry-download/Cargo.toml`. Программа поднимает локальный HTTP-сервер на `127.0.0.1`, открывает страницу в отдельном окне Wry и автоматически запускает скачивание небольшого файла. В журнал выводятся URL, предложенный и выбранный путь, результат callback и сравнение сохранённого файла с ожидаемыми байтами. Окно закрывается после callback или через 15 секунд ожидания.

Для двух загрузок одного URL: `cargo run --locked --manifest-path prototypes/wry-download/Cargo.toml -- --parallel`. Страница нажимает ссылку дважды, а локальный сервер задерживает тело ответа на 800 мс. Ожидаются два `START`, затем два `COMPLETE` с одинаковым URL и `callback_path=None`, затем `FILE ... matches=true` для обоих файлов. Этот режим проверяет доступные callback, но не решает связывание каждого завершения с конкретным файлом.

Успешный прогон: в журнале есть нужное число `COMPLETE ... callback_path=None success=true` и `FILE ... matches=true`, код завершения 0. Таймаут, ошибка файла и преждевременное закрытие окна дают код 1.

Загрузка разрешается только для точного URL локального сервера. Файл сохраняется в новой приватной папке системного временного каталога; после завершения процесса папка удаляется. Содержимое файла программа проверяет до выхода. Локальный сервер доступен другим процессам на этом Mac, но принимает не более восьми соединений и отдаёт только фиксированный тестовый файл. Веб-странице не выдаётся доступ к внутренним командам. Обработчик Wry настроен на отказ в разрешениях, но этот сценарий не доказывает охват всех системных запросов. Не открывайте в прототипе личные аккаунты и внешние URL.

UI-прогон не запускается в CI: GitHub проверяет формат, Clippy и сборку. Результат Mac-прогона записан в `docs/experiments/2026-11-07-wry-macos-download.md`.
