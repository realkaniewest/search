# Wry Windows runtime smoke

Изолированный исследовательский прототип для Windows CI. Он создаёт окно Tao и WebView2, загружает встроенный HTML и ждёт, пока JavaScript изменит заголовок страницы. Только точный заголовок `Search Windows smoke ready` завершает процесс с кодом 0. Внутренний таймаут 30 секунд после создания WebView и внешний таймаут CI ограничивают ожидание. Внешняя сеть и пользовательские данные не используются.

На Windows пустая строка в `with_additional_browser_args("")` заменяет аргументы Wry по умолчанию, среди которых есть отключение `msSmartScreenProtection`. Это исследовательская настройка для сохранения защиты; фактическое поведение SmartScreen тест не измеряет. Обработчик разрешений Wry возвращает `Deny`, включён incognito. [Wry указывает](https://docs.rs/wry/0.57.1/wry/struct.WebViewBuilder.html#method.with_incognito), что incognito на Windows требует WebView2 Runtime 101.0.1210.39 или новее; этот тест не проверяет удаление временных данных. Веб-странице не выдаётся IPC или доступ к внутренним командам.

Сборка и запуск закреплены в `.github/workflows/project-checks.yml`. Успешный запуск на GitHub runner подтвердит создание WebView2 и выполнение JavaScript в этой среде, но не видимые пиксели, доступность, работу на обычном Windows-ПК или полноту обработки разрешений. Если WebView2 Runtime отсутствует или GUI-сеанс недоступен, результат нужно фиксировать как ограничение среды и повторить на Windows под обычной учётной записью. [Wry API](https://docs.rs/wry/0.57.1/wry/struct.WebViewBuilder.html), [WebView2 Runtime deployment](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).
