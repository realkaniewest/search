# Search: первое экспериментальное окно

Это приложение этапа 1а, а не браузер для повседневного использования. Оно проверяет компоновку и границу между верхней панелью и веб-страницей. Вкладки всегда сверху. Панель и содержимое вкладок размещены в разных WebView.

## Запуск

Из корня репозитория: `cargo run --locked --manifest-path apps/search/Cargo.toml`.

На Linux нужны системные зависимости WebKitGTK 4.1 и GTK 3, как для остальных Wry-прототипов проекта. На Windows нужен WebView2 Runtime. Проверка сборки и запуска на каждой ОС проводится отдельно в CI и вручную.

В адресное поле можно ввести `Rust`, `Wikipedia`, `Excalidraw`, `local` либо адрес с соответствующего точного origin. Для Wikipedia разрешены точные адреса `www.wikipedia.org`, `en.wikipedia.org` и `ru.wikipedia.org`. Поиск на главной странице может переходить на английский или русский раздел. `local` указывает на `http://127.0.0.1:43127/`; страницу нужно запустить на этом порту самостоятельно. В обычной вкладке локальный адрес нужно открыть явно из адресной строки. Search открывает его в новом временном WebView вместо текущей страницы, поэтому история этой вкладки сбрасывается. После ухода на публичный сайт локальный переход нужно подтвердить повторным вводом адреса. `search:start` возвращает встроенную страницу. Поле не выполняет обычный поиск. Неизвестный адрес отвергается с сообщением в панели, введённый текст остаётся доступен для правки. Вкладка показывает загрузку и затем заголовок страницы, полученный от WebView. `+` создаёт новую вкладку; вкладки можно выбирать и закрывать. Доступны `⌘/Ctrl+T`, `⌘/Ctrl+L`, `⌘/Ctrl+W` и `⌘/Ctrl+R` при фокусе в верхней панели. Кнопка обновления перезагружает текущий сайт и недоступна на встроенной стартовой странице.

`--smoke` проверяет загрузку встроенной панели и стартовой страницы с таймаутом. `--security-smoke` работает с локальным тестовым сервером и считает блокировки перехода, нового окна, скачивания и вызовы обработчика разрешений. На macOS WebKit может отклонить камеру и геолокацию до вызова обработчика Wry, а на Linux WebKitGTK может отклонить новое окно до вызова обработчика Wry. Поэтому нулевой счётчик не означает, что действие было разрешено. Тестовый сервер отдельно проверяет результат со стороны страницы. Эти проверки не заменяют ручной сценарий на физическом компьютере.

## Граница безопасности обычного запуска

- Панель Search содержит IPC к Rust и встроенный HTML. Её навигация заблокирована, CSP запрещает внешние ресурсы и frames.
- WebView сайта не получает IPC или пользовательскую схему. Его верхняя навигация принимает только точный локальный origin и три HTTPS-сайта с разрешёнными редиректами. Это **не** блокировка субресурсов этих сайтов.
- Каждый WebView создаётся временным. Search отклоняет запросы разрешений, которые передаёт Wry, автоматические загрузки и `window.open`. На Windows дополнительные аргументы WebView2 заданы пустой строкой, чтобы не использовать отключение SmartScreen по умолчанию в Wry 0.57.1.
- Incognito сам по себе не доказывает изоляцию всех вкладок или отсутствие данных на диске. На Mac отрицательный тест двух запусков не обнаружил сохранения cookie и localStorage; остальные виды данных и другие ОС ещё требуют отдельной проверки.

В обычном запуске плитки стартовой страницы ведут к трём разрешённым сайтам. Дизайн описан в [брифе](../../docs/design-brief.md).

## Локальный MVP на macOS

Из корня репозитория собери и запусти внутреннюю сборку:

```sh
SEARCH_BUILD_HTTPS_PREVIEW=1 cargo build --locked --manifest-path apps/search/Cargo.toml
apps/search/target/debug/search-browser --https-preview
```

В режиме HTTPS-превью адрес или запрос можно ввести в активной вкладке или через `⌘T`. Поисковик переключается в меню быстрого поиска. Обычный профиль хранит сессию, историю и закладки в `~/Library/Application Support/Search Preview`. Постоянное хранилище данных сайтов доступно на macOS 14 и новее. Для временного просмотра запусти тот же бинарник с `--private-preview` или открой приватное окно из панели. Временное окно использует отдельное хранилище и не записывает историю или сессию обычного профиля.

Для загрузки введи прямой публичный HTTPS-адрес файла в интерфейсе загрузок и подтверди путь в системном диалоге. Search отменяет запросы на автоматическую загрузку со страницы, не перезаписывает существующие файлы и поддерживает отмену начатой загрузки. Выбор файла для передачи сайту проходит через отдельный системный диалог.

### Приёмка на macOS 27.0.1

- Проверены редирект с HTTPS на HTTPS, блокировка перехода на HTTP, отказ недоверенному сертификату и открытие доверенного сайта после таймаута.
- Запросы камеры, микрофона и геолокации завершились отказом со стороны WebKit в проверенных сценариях с временным профилем. Обработчик Search подтвердился для микрофона. Wry 0.57.1 не передаёт запрос геолокации в этот обработчик.
- Проверены сохранение тестовой HTTPS-загрузки через системный лист с меткой карантина, защита от перезаписи и очистка временного файла при отмене передачи. Локальная тестовая страница получила ровно один выбранный файл с ожидаемым содержимым через системный лист открытия. Отмена выбора оставила поле пустым.

## Окно разработки на macOS

В локальной HTTPS-сборке нажми «Окно разработки» в верхней панели. Введи адрес своего сервера, например `localhost:3000`, затем нажми «Инспектор». По адресу `localhost` Search открывает `127.0.0.1`. Для сервера на IPv6 введи `http://[::1]:3000/`. Для локального HTTPS сертификат должен быть доверенным и действительным для указанного IP-адреса. Переходы с локальной страницы остаются в пределах её схемы, адреса и порта. Подключения скриптов и других ресурсов страницы контролирует WebKit.

Окно разработки работает отдельно от обычного профиля. Его вкладки, запросы и данные сайтов не записываются в обычную историю или сессию. Обычная адресная строка Search сохраняет свою HTTPS-политику.
